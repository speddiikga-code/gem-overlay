# gem-setting: bugs found on Boseok's PC

Found while installing the kit on 2026-10-27 (Windows 11 23H2, Git for Windows 2.55, pwsh 7.6.9).
Each item was reproduced on this PC. The first four are fixed in Boseok's copy, one commit each:
`git -C "$env:DEV\gem-setting" log -p` shows the diffs against the kit as received.

## Fixed in Boseok's copy

1. **commit-msg deletes ordinary lines (high).** `generated (with|by) .*(claude|...|cursor|...)` is
   unanchored and matches inside words. `git commit -m "Fix duplicate rows generated by the DB cursor"`
   loses its only line and git aborts with "empty commit message"; a body line such as "Stubs
   generated with protoc for the Gemini endpoint." disappears silently. Fix: anchor it,
   `^[^[:alnum:]]*generated (with|by) \[?(claude|...)`, and run sed under `LC_ALL=C` so the
   class steps over the emoji's bytes.
2. **commit-msg strips human co-authors (medium).** The tool names match as substrings anywhere in
   the trailer: Cursor Kim, Devin Park, Jules Martin, Jean-Claude Roy and Haider Ali (aider) were all
   removed, against the README's "human co-authors stay". Fix: match the tools' addresses
   (`@anthropic.com`, `@openai.com`, `+Copilot@users.noreply.github.com`, `@cursor.com`,
   `@opencode.ai`, ...), plus a bare tool name with no address. OpenCode lines were not stripped at
   all, although the kit configures OpenCode.
3. **Repository hooks never run in linked worktrees (medium).** forward-hook, commit-msg and
   pre-push use `git rev-parse --git-dir`, which is `.git/worktrees/<name>` there. Claude Code's
   desktop app commits from worktrees. Fix: `--git-common-dir` (not `--git-path hooks`, which
   returns core.hooksPath and re-executes itself).
4. **A rerun from an older shell resets DEV, the language and the overlay (medium).** setup.ps1
   reads `DEV`, `AGENT_LANGUAGE` and `DEVSTARTER_OVERLAY` only from the process environment. A shell
   opened before the first run lacks them, so `.\setup.ps1` (the retry the summary suggests)
   rewrote DEV to `%USERPROFILE%\dev`, the rules to English, and dropped the overlay with
   "All steps finished.". It happened here. Fix: outside sandbox mode, load the saved user values first.
5. **Konsolas selection is invisible (low).** `selectionBackground` equals `background` (#060606).
   Set to #FFFFFF.

## Not changed

- **One .bak per file (low).** Every change overwrites `<file>.bak`, so after a second change the
  pre-kit original is gone, while the undo steps restore .bak as if it were the original. Two kit
  copies on one PC trigger it at once (the Terminal background path differs). Suggest: keep the
  first .bak, timestamp later ones.
- **Git LFS (medium).** With a global core.hooksPath, `git lfs install --local` fails ("Hook
  already exists: pre-push") and LFS repositories push pointers without objects. pre-push could
  call `git lfs pre-push` when `.gitattributes` has `filter=lfs`.
- **Missing forwarders (low).** pre-receive, update, post-receive, post-update, push-to-checkout,
  proc-receive and sendemail-validate are not forwarded, so a push-to-deploy bare repository stops
  deploying. Leave out reference-transaction and post-index-change: a forwarder makes every ref
  update spawn sh.
- **pre-push lint (low).** Always runs `check` and `format --check` on the working tree, even when
  lint.yml runs only one of them.
- **bootstrap.ps1 quoting (low).** `START.cmd -Dev "C:\My Dev\" -GitName "Boseok Kang"`: the `\"`
  breaks argv, git user.name becomes `Boseok Kang -Language Korean` and the rules come out in English.
- **office-view.ps1 (medium/low).** A relative publish/pdf target resolves against the process cwd,
  not `$PWD` (use `GetUnresolvedProviderPathFromPSPath`); `Resolve-Path`/`Test-Path` without
  `-LiteralPath` fail on names like `발표[최종].pptx`.
- **tools.ps1 (low).** The catch block calls `Get-Process -Name $null, ...` for gh-kind tools, which
  throws out of the handler.
- **Python install manager (medium).** On a PC with the new Python install manager, the WindowsApps
  `python.exe` is its alias, not the Store stub, and probing it (`uv python list`) silently
  installs a runtime. The overlay sets `UV_PYTHON_PREFERENCE=only-managed`; the kit could too.

## Docs

- START-HERE says "no .bak means the tool created it, delete it". `~\.gitconfig` never gets a .bak
  and held gh credential helpers here: deleting it loses them. Undo git key by key instead.
- The projects folder is written as `%USERPROFILE%\dev`; with `-Dev` it is elsewhere. Say `%DEV%`.
- The undo list misses the user PATH entry `~\.local\bin` and the uv Python; the winget example
  uninstalls Git, which many PCs had before the kit.
- README Quickstart says `Downloads\dev-starter`; the folder is `gem-setting`. The Tests section
  refers to `tests\run.ps1`, which the zip does not include (only an empty `tests\` folder).
- ASK-YOUR-AI says a failing step never stops the others; true only for winget/uv/git commands.

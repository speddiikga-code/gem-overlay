# gem-setting: bugs found on Boseok's PC

Found while installing the kit on 2026-10-27 (Windows 11 23H2, Git for Windows 2.55, pwsh 7.6.9).
Each was reproduced on that PC and is fixed in Boseok's copy, with an issue per significant bug in
his private repository `gem-setting` (issues #1 to #10, each closed by its fixing commit).
`git -C "$env:DEV\gem-setting" log -p 197d3dd..` shows every diff against the kit as received.

| Bug | Severity | Issue |
|---|---|---|
| commit-msg deletes ordinary lines such as "rows generated by the DB cursor" (one-line commits abort) | high | #1 |
| commit-msg removes human co-authors named Cursor, Devin, Jules, Jean-Claude, Haider; OpenCode lines not removed | medium | #2 |
| Repository hooks never run in linked worktrees (`--git-dir` instead of `--git-common-dir`) | medium | #3 |
| Rerun from a shell opened before the first run resets DEV, the language and the overlay | medium | #4 |
| A second change overwrites the only `.bak`, losing the pre-kit original | low | #5 |
| Git LFS repositories push pointers without objects under the global hooksPath | medium | #6 |
| uv probes the Python install manager alias, which silently installs a runtime | medium | #7 |
| Unquoted or backslash-quoted arguments bind to the wrong parameters; a broken `~/.claude/settings.json` aborts the run | low | #8 |
| office-view resolves relative paths against the process folder and fails on `[ ]` in names | medium | #9 |
| tools.ps1 crashes in its error handler for gh extensions | low | #10 |
| Konsolas selection color equals the background | low | none (cosmetic) |
| pre-push always ran both ruff commands; SKIP_LOCAL_CI did not skip LOCAL_CI_TESTS | low | none |
| Server-side hooks were not forwarded (push-to-checkout is left out on purpose: its presence disables git's own updateInstead checkout) | low | none |
| Docs: `.bak` rule, `~\.gitconfig` undo, `%DEV%` paths, undo list, Quickstart folder name, missing tests | docs | none |

Notes for the kit's author:

- Each fix is small and self-contained; the commit messages say why.
- `setup.ps1` now saves `UV_PYTHON_PREFERENCE=only-managed` and binds parameters by name only.
- A pre-kit `.bak` already overwritten by the old code cannot be recovered; the new rule only
  protects the `.bak` that exists now.
